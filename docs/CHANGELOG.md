## [v1.1.2] - 2026-10-31 (曲库扫描与 TF 卡排查)

### 🛠 优化与修复
- **曲库容量 32 → 80 首**：`MAX_TRACKS` 提到 80（单条 `TrackInfo` 约 132 字节，80 首约占 10.5KB 静态 RAM）。实测卡内 68 首可全部收录，不再被上限截断。
- **曲库扫描改为多轮收集**：大容量卡在 CYD 卡槽上会出现「目录读到一半就中断」，原来扫到 7 首就停。现在最多做 3 轮扫描，每轮把新发现的路径去重后补进列表，直到不再有新增。
- **SD 卡初始化提前到最前**：从「LCD 背光 / 音频初始化之后」移到 `settings_init()` 之后，让卡片在电源最干净的时机完成上电时序。
- **总线恢复序列加长**：空时钟由 1024 个（400kHz）增加到 **10000 个（100kHz，约 100ms）**——卡片若在软复位瞬间正处于 512 字节块传输中，需要约 4096 个时钟才能把剩余数据移出、回到空闲态。
- **新增后台重试挂载**：开机没挂上时，主循环每 30 秒重试一次，最多 4 次；一旦成功立即重扫曲库，无需手动点「重扫」。

### ⚠️ TF 卡结论更新（重要）
- **128GB SDXC 卡在 ESP32 软复位后必定挂载失败，且软件无法恢复**。
- 已穷尽验证：5 级降频（4M/1M/400k/100k/4M）、10000 空时钟总线恢复、`SPI.end()/begin()` 重初始化、SD 库默认初始化路径兜底、初始化顺序提前、后台 4 次定时重试 —— **全部无效**。
- **唯一恢复方式：物理断电或重新插拔卡片**（接触断开即让卡片内部状态机复位）。
- **建议**：日常使用换 **≤32GB FAT32** 卡；若必须用大卡，**每次烧录固件后重新插拔一次卡片**（外壳带电源开关的版本按一下开关即可）。

## [v1.1.1] - 2026-10-31 (黑屏问题修复)

### 🛠 修复
- **修复「校准页息屏后永久黑屏」**（v1.1.0 引入的回归）：
  - 现象：开机进入触屏校准页后约 30 秒，屏幕突然熄灭且触摸无法唤醒，只能重启。
  - 根因：v1.1.0 为省电在 `ui_update()` 开头加了「息屏直接 return」，但**校准页的触摸采样与 BOOT 键跳过逻辑全都写在 `touch_cal_ui_update()` 里**；一旦息屏，该函数不再执行，主循环里负责唤醒的触摸分支又因页面是校准页而被跳过 —— 形成死锁。
  - 修复：
    1. `ui_update()` 的息屏跳过对校准页例外；
    2. 主循环增加校准页分支，持续重置息屏计时，若已息屏则立即唤醒。
- **校准页强制满背光**：进入校准页时临时把背光拉到 100%，退出时恢复原亮度。此前若用户把亮度调到很低再进校准页，几乎看不到红色十字，只能盲点，会把校准参数点乱。
- **亮度安全兜底**：开机时若存储亮度 < 15%，自动修正为 50% 并写回，避免误触滑条后屏幕暗到被误判为"黑屏"。

### 📝 教训
- 「为省电而跳过渲染」这类全局优化，必须先确认该页面有没有把**交互逻辑**也放在渲染/更新回调里。本项目的校准页正是如此，一刀切跳过直接导致页面失能。

## [v1.1.0] - 2026-10-31 (续航优化)

### 🚀 新增功能
- **Wi-Fi 射频按需开关**: 联网完成 NTP 与天气同步后自动 `WiFi.mode(WIFI_OFF)` 关闭射频，之后每 30 分钟短暂唤醒一次刷新天气与时间。
  - 联网后保持 25 秒窗口；若窗口内未连上，自动续期 2 次（约 75 秒）后再关闭，避免错过同步。
  - 新增串口命令：`SAVE` / `WIFI:SAVE` 开启省电，`ALWAYS` / `WIFI:ALWAYS` 保持常连，`WEATHER` 手动唤醒刷新。
  - 同时开启 `WiFi.setSleep(true)`（modem sleep）。
- **CPU 频率三档自适应**: 播放音乐 240MHz / 亮屏待机 160MHz / 息屏待机 80MHz，由 `power_manager` 根据播放器状态与息屏状态自动切换。
- **诊断信息增强**: `[SYS] Uptime` 行新增 `CPU: xxxMHz` 与 `WiFi: ON / OFF(省电)`，便于验证省电策略是否生效。

### 🛠 优化与修复
- **息屏时跳过 UI 重绘**: 背光已关闭，重绘纯属浪费 CPU 与 SPI 带宽；唤醒后各页面会在下一次 update 自然刷新。
- **息屏时降低轮询频率**: 主循环延时由 4ms 放宽到 20ms，减少 CPU 唤醒次数。
- **息屏时关闭 RGB 灯**，避免额外耗电。

### 📊 实测效果（串口日志）
- 射频关闭后堆内存回收约 **33KB**（232KB → 265KB），说明 Wi-Fi 协议栈已完整释放。
- 亮屏待机 CPU 稳定在 **160MHz**；息屏后降至 **80MHz**。

> 功耗估算（无电流表实测，仅供参考）：Wi-Fi 射频关闭约省 80~100mA，CPU 240→160MHz 约省 15~20mA，息屏后 80MHz 再省约 30~40mA。背光仍是最大耗电项，低亮度使用收益最明显。

## [v1.0.0] - 2026-10-30 (版本统一与工程收尾)

### 🚀 新增功能
- **三角洲每日密码页正式接入**: 在「摸鱼大厅」新增第三张卡片入口（原页面已在路由中注册，但全项目无任何跳转调用，属于不可达死代码）。页面返回键改为回到摸鱼大厅而非主页。
- **新增独立硬件诊断环境 `[env:diag]`**: `src/diag_main.cpp` + `tools/serial_capture.py`，可一键烧录诊断固件并通过串口定位 SD 卡 / 音频链路问题，不影响正式固件编译。

### 🛠 优化与修复
- **重写音频输出驱动 `AudioOutputDAC`（绕开 I2S）**:
  - 原实现继承 `AudioOutputI2S(0, INTERNAL_DAC)`，但该库把 DAC 模式的 `sample_rate` **硬编码为 44100**，与 8kHz 演示 WAV 不匹配，实测表现为「既不出声、播放进度也不推进」；其 `i2s_set_dac_mode(BOTH_EN)` 还会同时占用 GPIO25，而 GPIO25 正是 XPT2046 的软件 SPI 时钟线。
  - 新驱动直接按采样率软件节流写 DAC2(GPIO26)，每 48 个采样让出一次 CPU，完全不碰 I2S 与 GPIO25。修复后演示曲可按正确速率播放（实测 11 首 / 约 40 秒，与 3.9 秒/首吻合）。
- **新增待机中点偏置**: 上电即把 DAC2 钳在 1.65V，显著降低功放输入悬空导致的自激嗡声。
- **修复 `audio_test_beep()` 空实现**: 该函数曾被改为空函数（`// Ignored in media mode`），导致「硬件自检 → 测音频 1 秒」按钮完全无响应。现改为直接驱动内部 DAC2(GPIO26) 输出方波，并保留防爆音时序；播放中自动跳过以免抢占 DAC。
- **三角洲密码页健壮性**: HTTP 请求增加 4 秒连接/读取超时，避免无网或弱网时阻塞 UI 主循环；Wi-Fi 未连接时给出明确引导文案。
- **清理死代码**: 删除 `src/wallpaper.h`（628KB，全项目零引用）。
- **版本号统一**: `main.cpp` 注释、README 徽章与启动日志、`GPIO.md`、`TEST_PLAN.md`、`ARCHITECTURE.md` 全部对齐至 **v1.0.0**（此前 `config.h` 已是 v1.0.0，但其余文档仍停留在 v0.1.0）。
- **文档数据更新**: 修正 README / ARCHITECTURE 中过时的编译占用数据（原 413KB / 31.6% → 实测 1,639,273 B / 52.1%）。
- **`platformio.ini` 移除硬编码 `upload_port = COM9`**: 改为由 PlatformIO 自动探测，换机换口不再烧录失败。

### ⚠️ 已知硬件问题 (实测结论)

- **TF 卡（128GB SDXC）挂载不稳定**
  - 实测现象：物理重新插拔卡 + USB 断电重插后**可以正常挂载**（识别为 SDHC 128000MB，成功扫描出 7~32 首 MP3）；但只要 ESP32 软复位一次，后续所有启动都挂载失败。
  - 已排除软件因素：5 级降频重试（4MHz→1MHz→400kHz）、总线恢复序列（1024 个空时钟）、`SPI.end()/begin()` 重初始化、SD 库默认初始化路径兜底，全部无效。
  - 裸 SPI 命令探测：未挂载时 `CMD0` 恒返回 `0xFF`，说明 MISO 上没有任何器件应答，属电气层问题。
  - **结论**：128GB SDXC 卡对该板卡槽的供电与信号完整性余量不足。**建议换用 ≤32GB、FAT32 格式的卡**，这是 ESP32 SPI 模式最稳的组合。
- **扬声器无声：最终确认为「喇叭本身损坏」**（2026-10-31 结案）
  - **最终结论**：板载功放工作正常，问题出在**喇叭单元本身是坏的**。更换新喇叭后即恢复正常。
  - 厂商在线烧录页对 8002 功放的接线说明（原文）：「**喇叭 8002：GPIO26 DAC2 → AUDIO_IN，GPIO4 LOW 开启功放**」——即音频走内部 DAC2(GPIO26)、`GPIO4` **低电平**使能功放。
  - 固件据此配置：`AUDIO_OUTPUT_USE_PWM = 0`，`amplifier.cpp` 中 `AMP_ON_LEVEL = LOW`。
  - **排查过程中的两次误判（记录以免重蹈）**：
    1. 曾判定「GPIO26 到功放输入开路」——实际是坏喇叭不发声，任何激励都听不到，被误读成信号没到功放；
    2. 曾依据产品手册「预留音频接口 / AUDIO_IN 方向为输入」判定「板上没有功放芯片」——实际板上有 8002，手册的「预留」指的是该接口功能由用户程序定义，并非没有功放。
  - **教训**：怀疑信号链路之前，先用一个**已知完好的负载**（另一个喇叭 / 耳机）替换验证，能避免大量误判。

## [v0.3.1] - 2026-10-16 (音频通道冲突修复)

### 🛠 优化与修复
- **修复播放 BGM 时触控失灵/死机**: `ESP8266Audio` 的 `AudioOutputI2S(0, INTERNAL_DAC)` 默认调用 `i2s_set_dac_mode(I2S_DAC_CHANNEL_BOTH_EN)`，会同时占用 GPIO25 与 GPIO26，而 GPIO25 正是 XPT2046 触摸屏软件 SPI 的时钟线。
- 新增 `AudioOutputCYD` 子类，覆写 `begin()/stop()`，强制 `I2S_DAC_CHANNEL_LEFT_EN`，将 DAC 限定在 GPIO26(DAC2)，并在每次音频状态切换后调用 `restoreTouchPin()` 恢复 GPIO25 为数字输出。

## [v0.1.0] - 2026-10-06 (阶段一交付: 硬件全通与底层架构奠基)

### 🚀 新增功能
- **全硬件驱动与模块化分层**:
  - `src/hardware/`: 完成 LCD (ST7789)、Touch (XPT2046 独立软 SPI)、Audio (GPIO26)、Amp (GPIO4)、Battery (GPIO34 ADC)、RGB (LEDC PWM)、Buttons (BOOT GPIO0) 封装。
  - `src/storage/`: 增加 `SDCard`、`Scanner`、`Database` 模块，全面支持非阻塞 `DEMO_MODE`，未插入 TF 卡时绝不死锁。
  - `src/player/`: 实现显式播放器有限状态机（`STOPPED`, `LOADING`, `PLAYING`, `PAUSED`, `SEEKING`, `FINISHED`, `ERROR`），支持顺序播放、单曲循环、全部循环、随机播放。
  - `src/system/`: 引入基于 NVS 的持久化配置管理 (`SettingsManager`)、自动息屏节能 (`PowerManager`)、竞赛级运行遥测 (`Diagnostics`)。
  - `src/ui/`: 构建 320x240 大指触电容感触控界面（启动屏、主菜单、播放器、曲库列表、系统设置、硬件自检专页）。
- **音频防爆音时序**:
  - 实现 `GPIO4` 功放使能延迟启动与提前关断时序，彻底解决板载功放休止符底噪与上电 POP 音。
- **竞赛级数据接口**:
  - 串口提供统一标签化调试输出（`[BOOT]`, `[DISPLAY]`, `[TOUCH]`, `[AUDIO]`, `[AMP]`, `[BATTERY]`, `[SD]`, `[PLAYER]`, `[UI]`, `[SYS]`, `[ERROR]`）。
  - 支持实时输出 Free Heap、历史最低水位、运行时间、供电电压与后台任务负载。

### 🛠 优化与修复
- 修复 ST7789 驱动色彩反色问题（强制 `tft.invertDisplay(false)`）。
- 消除 `TFT_WIDTH`/`TFT_HEIGHT` 宏定义重定义冲突与头文件重名问题。
- 优化 XPT2046 电阻式触摸屏 3 次中值滤波与压力门限防抖。
