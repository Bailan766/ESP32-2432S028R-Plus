# Bailan MP3 Player (摆烂 MP3 播放器)

[![PlatformIO](https://img.shields.io/badge/PlatformIO-Compatible-orange.svg)](https://platformio.org/)
[![Hardware](https://img.shields.io/badge/Hardware-ESP32--2432S028R--Plus-blue.svg)](docs/GPIO.md)
[![Status](https://img.shields.io/badge/Version-v1.1.3-green.svg)](docs/CHANGELOG.md)

基于 **ESP32-2432S028R Plus** 一体化电阻触屏开发板（CYD Plus）打造的开源、模块化、高可靠嵌入式便携式 MP3 播放器，兼具科技创新与智能硬件竞赛展示设计标准。

---

## 📌 核心特性

- **全硬件驱动打通**: 屏幕 (ST7789 320x240 横屏)、电阻触摸 (XPT2046 独立软 SPI)、音频输出 (GPIO26)、功放使能 (GPIO4)、RGB 灯 (PWM)、电池检测 (GPIO34 ADC)、物理按键 (BOOT)。
- **硬件级静音与消底噪**: 通过 `AMP_ENABLE (GPIO4)` 严格配合音频信号建立延时，彻底根除板载功放（NS4168）的休止符白噪声、底噪及开关爆音（Anti-POP）。
- **零 TF 卡优雅开机 (DEMO MODE)**: 在未插卡情况下不卡顿、不死循环，自动切换至内置 5 首芯片旋律与内置测试小说《摆烂修仙传》，UI、触摸与动效全功能正常运转。
- **全功能 TXT 小说阅读器**:
  - **7,445 字全量点阵中文字库**: 内置 GB2312 常用汉字、全角标点，支持 UTF-8 与 GBK/GB2312 编码自动识别，杜绝乱码。
  - **大文件流式分页**: 毫秒级按需加载，支持 10MB+ 大长篇小说，64 级翻页栈回退，NVS 自动书签记忆。
  - **4 款护眼配色**: 暗黑水墨、羊皮纸卷、豆沙护眼、深夜星河一键换肤。
  - **摸鱼神器 BGM 伴读**: 阅读时可边看书边听卡内音乐，支持悬浮面板一键快进、跳转章节与背光调光。
- **摸鱼大厅 (经典益智与解压小玩具)**:
  - **2048 数字消除**: 支持滑屏手势与虚拟方向十字盘双操作，高对比度色彩方块，分数与最佳纪录自动持久化存储至 NVS，伴随合成音效。
  - **电子木鱼 (功德+1)**: 沉浸式木质顿挫敲击声，浮现“功德 +1”飘字动效，支持“自动敲击”挂机摸鱼攒功德模式。
- **WiFi 智能时钟与实时气象看板**:
  - **NTP 毫秒级时间校准**: 自动同步北京时间，年-月-日-星期大字体实时更新。
  - **实时全国天气**: 获取当地温度、气象状态（晴/多云/阴/雨/雪）及空气湿度。
  - **手机 Web AP 免密码配网**: 支持手机直连开发板热点快速录入 Wi-Fi。
- **模块化工程解耦**: 代码按 `hardware/`、`storage/`、`player/`、`reader/`、`game/`、`system/`、`ui/` 分层，逻辑清晰，易于二次开发。
- **竞赛级遥测诊断 (SystemDiagnostics)**: 统一串口格式输出（波特率 115200），实时监控 Free Heap、历史最低水位、运行时间、供电电压及播放器核心状态机。

## 🛠 编译与烧录指南

### 步骤 1: 环境准备
1. 推荐在 VS Code 中安装 **PlatformIO IDE** 插件；
2. 如果使用命令行，确认电脑已安装 PlatformIO Core (`pio`)。

### 步骤 2: 打开项目
在 VS Code 中点击 `File -> Open Folder`，打开本工程根目录：
`c:\Users\Administrator\Desktop\ESP32-2432S028R-Plus`

### 步骤 3: 编译项目
在 VS Code 底部状态栏点击 `√` (Build) 按钮，或在终端执行：
```bash
pio run
```
> **实测编译占用 (v1.0.0)**:
> - RAM: 57,052 字节 (17.4%)，剩余约 270KB 可用堆内存。
> - Flash: 1,639,273 字节 (52.1%)，其中约 253KB 为中文点阵字库（存于 Flash，不占 RAM）。

### 步骤 4: 烧录固件
> **⚠️ 烧录前关键注意事项**:
> 若开发板外接了 GPS 模块（GT-U7），**必须拔掉接在 GPIO1 的连线**，因 GPIO1 与板载 CH340 芯片的 USB TX 共用，插上会导致串口烧录握手失败。

通过 USB 数据线将 ESP32-2432S028R Plus 连入电脑，确认设备管理器中的端口（当前识别为 `COM9`）：
```bash
pio run --target upload --upload-port COM9
```

### 步骤 5: 开启串口调试监视器
```bash
pio device monitor -b 115200
```
开机将观察到统一标签化的日志输出：

## 🔊 音频接口说明

板载 **8002 单声道功放**，喇叭直接插 **CN1（2.0P 音频接口）** 即可发声，无需外接功放模块。

厂商给出的接线定义：

> **喇叭 8002：GPIO26 DAC2 → AUDIO_IN，GPIO4 LOW 开启功放**

对应固件配置（`include/config.h` / `amplifier.cpp`）：

| 项 | 值 | 说明 |
| :--- | :--- | :--- |
| `AUDIO_OUTPUT_USE_PWM` | `0` | 音频走内部 DAC2，比 PWM 干净 |
| `AUDIO_DAC_PIN` | `26` | AUDIO_IN，接 8002 的输入端 |
| `AMP_ENABLE_PIN` | `4` | AUDIO_EN，**低电平使能**功放 |
| `AMP_ON_LEVEL` | `LOW` | 播放时拉低开启，待机拉高关断消底噪 |

> **踩坑提示**：本项目曾在「喇叭无声」上排查了很久，最终发现是**喇叭单元本身损坏**。
> 怀疑信号链路之前，先用一个已知完好的负载（另一个喇叭）替换验证，能省下大量时间。

### 备用方案：外接功放

若板载 8002 损坏，可用 PAM8302 等外接模块：CN1 的 GPIO26 → 模块 `IN+`，GPIO4 → 模块 `SD`，模块 `VIN`/`GND` 从板子取电，喇叭接模块输出。若改用 GPIO27 输出，把 `AUDIO_OUTPUT_USE_PWM` 改为 `1` 即可切换到 40kHz PWM（建议在 `IN+` 前加 1kΩ + 10nF 低通）。

## 🎯 触屏校准（触摸失灵时的救命通道）

**长按实体 BOOT 键 → 直接进入触屏校准页**，不依赖触摸。

这条入口专为「校准数据损坏导致所有按钮错位」的情况准备：此时点哪里都不对，无法通过设置页进入校准，只能用物理按键。

校准页会自动把背光拉到 100%，按屏幕四个角的红色十字中心依次点击即可；校准页内**短按 BOOT 键**可跳过退出。

> 校准完成后参数写入 NVS，下次开机自动加载。
> 若加载到的参数异常（主系数接近 0，说明采样点被打乱、矩阵转置），固件会打印自检失败日志并强制重新校准。

## 💾 TF 卡使用说明（重要）

### 烧录固件后需要重新插拔卡片

**128GB 及以上的大容量卡在本板卡槽上，ESP32 软复位（重新烧录、按 RESET）后必定挂载失败，且软件无法恢复。**

已穷尽验证：5 级降频（4M/1M/400k/100k）、10000 个空时钟总线恢复、`SPI.end()/begin()` 重初始化、SD 库默认路径兜底、初始化顺序提前、后台 4 次定时重试 —— 全部无效。

> **恢复方式**：物理断开卡片电源即可 —— 重新插拔一次卡，或按外壳上的电源开关。
> **推荐**：换 **≤32GB、FAT32** 的卡，这类卡软复位后通常能正常重新初始化。

### 曲库容量与扫描

- 曲库上限 **80 首**（`MAX_TRACKS`），单条记录约 132 字节。
- 优先扫描 `/Music` 目录，不存在则扫描根目录。
- 扫描采用**多轮收集**：大容量卡可能「目录读到一半中断」，固件会最多重试 3 轮把漏掉的补回来。
- 开机没挂上时，主循环每 30 秒后台重试一次（最多 4 次），成功后自动重扫曲库。

## 🔋 续航优化 (v1.1.0)

### 1. Wi-Fi 射频按需开关

联网完成 NTP + 天气同步后**自动关闭射频**，之后每 30 分钟短暂唤醒一次刷新数据。

```
开机 → 连接 Wi-Fi（保持 25 秒窗口）→ 同步时间/天气 → WiFi.mode(WIFI_OFF)
                                          ↓
                              每 30 分钟唤醒 25 秒刷新一次
```

- 窗口内没连上会自动续期 2 次（约 75 秒）再关闭，避免错过同步
- 串口命令：`SAVE` 开省电 / `ALWAYS` 常连 / `WEATHER` 手动唤醒刷新
- 同时开启 `WiFi.setSleep(true)`（modem sleep）

### 2. CPU 频率三档自适应

| 状态 | 频率 | 说明 |
| :--- | :--- | :--- |
| 播放音乐 | 240MHz | 解码 + DAC 节流需要余量 |
| 亮屏待机 | 160MHz | UI 流畅，功耗约为 240MHz 的 2/3 |
| 息屏待机 | 80MHz | Wi-Fi 要求的最低频率 |

### 3. 息屏时的额外优化

- 跳过所有页面重绘（背光已关，重绘纯属浪费 CPU 与 SPI 带宽）
- 主循环延时由 4ms 放宽到 20ms，减少 CPU 唤醒次数
- 关闭 RGB 灯

### 4. 验证方法

串口每 10 秒打印一次状态，可直接观察省电策略是否生效：

```text
[SYS] Uptime: 35s | Heap: 265500B (Min:224164B) | Batt: 4.28V | TF: 未检测到 | Player: 已停止 | CPU: 160MHz | WiFi: OFF(省电)
```

> 背光仍是最大耗电项（满亮约 100~150mA），日常把亮度降到 40% 以下收益最明显。

## 🔍 硬件诊断环境 (SD 卡 / 音频链路排查)

当出现「TF 卡读不到」「扬声器没声音」这类问题时，可烧录独立的诊断固件，通过串口日志定位是软件引脚配置问题还是硬件问题：

```bash
pio run -e diag -t upload          # 烧录诊断固件 (只编译 src/diag_main.cpp)
python tools/serial_capture.py COM9 30   # 抓 30 秒串口日志
```

诊断固件会做三件事：

1. **SD 总线 × 片选交叉扫描**：遍历 4 组 (SCK/MOSI/MISO) × 19 个候选 CS，用裸 `CMD0` 命令探测卡片是否存在；
2. **MISO 引脚扫描**：固定 CS=5，遍历 20 个可作输入的引脚；
3. **音频链路测试**：分别用 DAC2(GPIO26) 与多组 I2S 引脚组合输出方波，人工听音确认。

> 判读要点：`CMD0` 返回 `0xFF` 表示 MISO 上完全没有器件应答（硬件层问题）；
> 返回 `0x01` 才是卡片正常响应。MISO 扫描中若只有浮空引脚（如 GPIO35/26/21）返回 `0x00`，属于误报，可忽略。

烧回正式固件：`pio run -e esp32dev -t upload`

## 🧪 硬件测试步骤 (无 TF 卡直接测)

进入屏幕操作：
1. **主界面**: 点击 `Music`，立即进入播放器界面，屏幕动态渲染 16 频段音频频谱，板载扬声器播放内置芯片旋律，RGB 灯伴随旋律律动；
2. **触控测试**: 点击屏幕下方 `||` 暂停、`>` 播放、`|<` 上一首、`>|` 下一首、`ALL/ONE/RND` 循环模式切换；
3. **实体按键测试**: 短按板载 `BOOT` 键可播放/暂停，长按 `BOOT` 键可切歌；
4. **硬件自检专用页面**:
   - 返回主页，点击 `Settings` -> `硬件自检 Test`；
   - 观察 `LCD [OK]`、`TF Card NOT FOUND`、`电池实时电压/ADC`；
   - 点击 `[测音频 1s]`：扬声器播放 1 秒纯净蜂鸣测试音后自动关断；
   - 点击 `[切换色彩]`：RGB 灯在 红 -> 绿 -> 蓝 -> 白 -> 灭 循环轮播；
   - 按下板载 `BOOT` 键：屏幕即时显示 `[PRESSED 按下]`；
   - 点击屏幕任意角落：下方实时显示当前点击像素 `XY:(xxx, yyy)` 与压力读数。
